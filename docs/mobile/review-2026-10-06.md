> Snapshot of a review of `tawara/0.14-mobile` at 71f00e8, taken on 2026-10-06. Many items have since been fixed on `main`; see `git log` and `src/mobile.rs`'s Known limitations for the current state.

# iced_mobile: review, problems, and a plan to make it easy for agents to use

## 1. What it is

**iced** is a Rust GUI library built on the Elm architecture: you keep state, define messages, write `update`, and write `view`. It opens windows through winit and draws with wgpu (GPU) or tiny-skia (CPU). Upstream supports Windows, macOS, Linux and the web (`README.md:31`). Its maintainer has turned down mobile support several times. iced-rs/iced#302 is labelled "out of scope". PRs #2952, #3099 and #3245 were closed, one with the comment "I have no interest in maintaining anything related to Android or iOS".

**This fork** (`patricksmithlaravel/iced_mobile`) is a GitHub fork of iced-rs/iced.

- **`master` is upstream.** It is byte-identical to upstream master: 0.15.0-dev, with no mobile code.
- **The mobile work is on `tawara/0.14-mobile`.** That branch is iced 0.14.1 plus three commits:
  - **38237dd29** fixes an event-loop spin on stale redraw deadlines. It is upstream's own commit, the tip of iced-rs/iced's `0.14` branch, so it is not fork code. The fix is correct.
  - **0b02176ee** makes iced run on Android and iOS. It adds `set_android_app`, holds actions back until the first `Resumed` on Android, drops and rebuilds surfaces on Android suspend/resume, adds a `Lifecycle` enum with an `on_lifecycle` hook, and changes key conversion for mobile.
  - **71f00e847** puts iOS windows into the UIScene (new file `winit/src/scene.rs`). Apps built with the iOS 27 SDK need this.
- **The real delta is small.** Against upstream's 0.14 tip it is 391 lines added and 19 removed, across 7 files. All of it is in `winit/` and Cargo files; `scene.rs` alone is 165 lines.
- **Who uses it:** Tawara, a Mochimo wallet (repos Tawara-mobile and Tawara-wallet), which pins `iced_winit` at rev `71f00e8`. Tawara's `docs/DECISIONS.md` D32 says the scene work was moved here so other apps could be built on the fork.

**State:** a prototype that works for the one app using it.

What is sound:
- The Android surface handling follows winit 0.30's rules. Surfaces are dropped before `suspended()` returns, and android-activity waits for that.
- Holding actions back until the first `Resumed` keeps them in order.
- `scene.rs` works. On an iOS 27 simulator, UIKit refuses to launch the app without the scene manifest and renders it with the manifest.
- `scene.rs` reuses winit's objc2 0.5 versions, so it adds no extra copy. (A fresh downstream resolve already duplicates the objc2 stack anyway, because softbuffer 0.4.8 pulls in objc2 0.6.)
- Desktop and wasm still work: `ICED_TEST_BACKEND=tiny-skia cargo test --workspace` gives 134 passed. The Windows and wasm checks pass.
- The commit messages are excellent. They are the only documentation.

What is missing: docs, an example, CI, a tag, and any way to find the mobile branch from the repo front page. A default iced app built for iOS shows no text.

The Android findings below come from reading source, `cargo check`, and Tawara's CI output. No NDK or emulator was available for this review. The iOS findings were reproduced on an iOS 27 simulator.

## 2. What's wrong, ranked

### A. Correctness bugs

**A1. Text is invisible on iOS and Android with default settings.**
*High · confirmed on the iOS simulator (screenshots plus a host shaping probe); Android from source · `graphics/src/text.rs:116-134`, `graphics/src/settings.rs:40-47`, `graphics/src/text.rs:325-333`*

The chain of causes:
1. fontdb 0.23 loads no system fonts on either platform. It has no Android branch, and iOS falls into its Linux branch, which scans `/usr/share/fonts` and similar (`fontdb-0.23.0/src/lib.rs:400-475`).
2. iced's font system therefore holds only `Iced-Icons`, plus Fira Sans if the non-default `fira-sans` feature is on.
3. The default font is `SansSerif`, which cosmic-text maps to "Open Sans", which is absent.
4. `Shaping::Auto` uses Basic shaping for ASCII text. Basic shaping takes the first font the fallback iterator returns, which is Iced-Icons. Every glyph becomes its empty `.notdef`.

The result is buttons with no labels and no error message. Turning on `fira-sans` alone only fixes Advanced-shaped text: the text_input placeholder, text_editor, rich_text, and non-ASCII strings. Upstream already solves this exact problem for wasm32: `settings.rs:40-47` swaps in Fira Sans there, and `examples/counter/Cargo.toml` enables `fira-sans` on wasm32. The fork never extended that to mobile.

Fira Sans covers Latin, Greek and Cyrillic only: no CJK, kana, Hangul, Arabic, Hebrew, Devanagari, Thai or emoji. Even after the font fix, such text stays invisible unless the platform font directory is loaded (`/system/fonts` on Android; on iOS, sandbox read access must be checked on a device). Apps can do that today through `iced::advanced::graphics::text::font_system()` → `raw()` → `db_mut().load_fonts_dir(..)`.

Workarounds today:
- `fira-sans` plus `.default_font(Font::with_name("Fira Sans"))`, or
- the `advanced-shaping` feature, or
- an embedded font set as the default.

**A2. A drag that starts on a button (or other interactive widget) inside a scrollable does not scroll.**
*High · confirmed on the simulator and headless with `iced_test` · `widget/src/scrollable.rs:807-844, 925-941`, `widget/src/button.rs:302-313`*

`scrollable` gives each event to its content first and returns if the content captured it. Touch scrolling only starts on a `FingerPressed` that nobody captured. Buttons, text_input, checkbox, toggler, radio, slider, mouse_area and pick_list all capture `FingerPressed`. So a list of tappable rows only scrolls when the drag starts in the gaps between rows.

- On the simulator, a 60-button list did not move when swiped.
- In `iced_test`, pressing on a button gave no scroll, while pressing in the 10px gap scrolled 1:1.
- There is no momentum scrolling.

This is upstream issue iced-rs/iced#2004, open since 2023 and inherited unchanged. A slop threshold plus `FingerLost` is not enough of a fix, because checkbox, toggler and radio publish their message on press. The scrollable would need to hold the press back, or those widgets would need to commit on lift.

**A3. Android: recreating the Activity freezes the app, and relaunching after an exit closes it immediately.**
*High · confirmed from source; Tawara's CI saw the same symptom (check A18, "shows nothing"); not run on a device here · `winit/src/lib.rs:144`; `winit-0.30.13/src/platform_impl/android/mod.rs:289-293`; `android-activity-0.6.x/src/native_activity/glue.rs:400-408`*

The freeze:
1. Without a full `android:configChanges` list, rotating the device, toggling dark mode (uiMode), or changing locale or font scale makes Android destroy and recreate the Activity.
2. android-activity's `onDestroy` blocks the Java UI thread until `android_main` returns. It does this for both NativeActivity and GameActivity.
3. winit 0.30 only logs `MainEvent::Destroy` with a "TODO", and iced never sees it, so `android_main` never returns.
4. The screen freezes. The next touch produces an ANR.

The relaunch failure:
1. If the iced loop does end, for example through `iced::exit()`, Android usually keeps the process alive.
2. The next launch calls `android_main` again, and `builder.build()` returns `RecreationAttempt`. winit allows one event loop per process (`event_loop.rs:118-119`).
3. `.expect("Create event loop")` panics, android-activity catches the panic, and the Activity closes.
4. This repeats on every launch until the process dies.

The fork ships no manifest and does not warn about this. Even a full `configChanges` list cannot prevent every recreation. The real fix has to happen in winit: exit on Destroy and allow the loop to be recreated. winit PR #4739, open against v0.30.x, does both.

**A4. Stale minimum versions: winit 0.30.12 means no typed text on Android, and softbuffer 0.4.6 means no Android build.**
*Medium · confirmed by `cargo check` and source diff · `Cargo.toml:242`, `Cargo.lock:7482-7483`, `Cargo.toml:227`, `Cargo.lock:5464-5465`, `winit/src/conversion.rs:279-287`, `widget/src/text_input.rs:1015`*

- **winit.** The workspace allows `winit = "0.30"` and the lock pins 0.30.12. In 0.30.12, Android's `KeyEvent::text` is always `None` (`winit-0.30.12 android/mod.rs:459`); 0.30.13 fills it in. The fork has to read `event.text` on mobile, because `modifier_supplement` does not exist there, and text_input only inserts characters from `text`. With 0.30.12, typing inserts nothing, while Backspace and Enter still work.
  - A fresh downstream lockfile resolves 0.30.13 and works.
  - Any app whose lockfile already holds 0.30.12 keeps it and gets no warning.
- **softbuffer.** The lock pins 0.4.6, which has no Android backend; it arrived in 0.4.7. In-repo `cargo check -p iced --target aarch64-linux-android` fails with 20 errors inside softbuffer that never mention Android.

**A5. Exiting is broken on both platforms.**
*Medium · `iced::exit()` abort confirmed on the simulator (crash report written); the rest confirmed from source plus the simulator · `winit/src/lib.rs:393-397, 538-541, 1178-1191, 1437, 1565-1587`*

- **iOS, `iced::exit()`:** winit's `exit()` does nothing on iOS, and `exiting()` is always false (`winit ios/event_loop.rs:88-96`). Once `run_instance` returns on `Event::Exit`, the next callback hits `start_send(...).expect("Send event")` (lib.rs:397) inside an `extern "C"` run-loop observer. The panic cannot unwind there, so the process aborts with SIGABRT.
- **Closing the last window, both platforms:** iced only exits on `WindowEvent::Destroyed`, which mobile winit never sends. So `window::close` on the last window leaves a live app with a black screen (iOS, seen on the simulator) or a loop with no window that ignores input (Android).
- **Android Back key:** winit marks every key except the volume keys as handled (`android/mod.rs:374, 426-435`). For apps targeting API below 36, Back therefore never finishes the Activity. The app does receive it, as `Named::BrowserBack`.

**A6. On iOS, Return never submits a `text_input` or adds a newline in `text_editor`, and Tab is dropped.**
*Medium · confirmed by simulator screenshot and a host `iced_test` repro · `winit/src/conversion.rs:242-290`, `widget/src/text_input.rs:1022-1055`, `widget/src/text_editor.rs:1209-1224`*

winit on iOS delivers every `insertText:` character as `Key::Character`, so Return arrives as `Character("\n")` (`ios/view.rs:543-575`). text_input drops control characters and only submits on `Named::Enter`, and text_editor works the same way. The fix is to map `"\n"`/`"\r"` to Enter and `"\t"` to Tab under `cfg(target_os = "ios")`. One side effect: dictated or pasted text containing a newline would then trigger submit.

**A7. Two Android window edge cases panic.**
*Low · confirmed from source · `winit/src/lib.rs:274, 357-363`, `winit/src/window.rs:61-70`, `wgpu/src/window/compositor.rs:308-311`*

- **Opening a window while suspended.** Holding actions back stops for good at the first `Resumed`. A `window::open` handled while suspended after that creates a window with no native window. `create_surface(...).expect("Create surface")` then panics, and the tiny-skia path panics the same way.
- **A second window.** Android winit has one native window and one unit `WindowId`. A second `window::open` makes a second Vulkan surface on the same window, and wgpu-hal panics at `vulkan/instance.rs:525` (`"AndroidSurface failed"`).

Single-window apps that only open a window at boot are not affected.

**A8. On iOS, `window::Event::Opened` reports the wrong size, and the `scene.rs` doc gives the wrong reason for the event order.**
*Low · confirmed · `winit/src/window/state.rs:64`, `winit/src/scene.rs:11-14`*

`Opened` carries the safe-area size (402×778), then `Resized` carries the full bounds (402×874). One verifier saw `Opened{0x0}` plus `Resized(0x0)` on the first launch of a fresh simulator; that is the window-first path. The doc says iced makes windows on `Resumed`, but it actually makes them from a proxy user event. Treat `Resized` as the real size on iOS.

**A9. Touch leaves a "sticky hover".**
*Low · confirmed by screenshots · `winit/src/window/state.rs:166-174`*

Touches set `cursor_position` and nothing clears it, because mobile winit never sends `CursorLeft`. The last widget tapped stays in its hovered style, and tooltips stay open. The fix must clear the cursor only after the batch containing the final lift has been dispatched. Clearing it inside `State::update` would break `on_press`.

**A10. A graphics setup failure on iOS is silent.**
*Low · confirmed from source · `winit/src/lib.rs:449, 543-546, 576, 757-765`*

`Control::Crash` stores the error without logging it. The error is only read after `run_app` returns, which never happens on iOS. The window was created hidden and is never shown, so the user sees a black screen and nothing in the log. With default features, a wgpu failure falls back to tiny-skia, so you only hit this in wgpu-only builds or with a forced backend.

**A11. `iced/sysinfo` breaks the iOS build once libc is 0.2.190 or newer.**
*Low · confirmed · `winit/Cargo.toml:19, 36-37`*

libc 0.2.190 restricted `mach_task_self` and similar to macOS, and sysinfo 0.33.1 still uses them on iOS. The repo's own lock (libc 0.2.178) builds; a fresh downstream app does not. Workaround: `cargo update -p libc --precise 0.2.189`.

**A12. Two latent surface hazards.**
*Low · `winit/src/lib.rs:637, 1110, 1138-1145`*

- Whether a surface exists is tracked twice: by `is_suspended` and by `Option<Surface>`. The `None` branch before present is dead code today.
- The surface-Lost path builds the new surface before dropping the old one. This is upstream code. On Android, a second surface on the same window fails.

Neither triggers today. Make surface `None` the single source of truth when you next touch this code.

### B. Platform risks

**B1. `Lifecycle::Suspended` means something different on each platform, and on iOS it fires for brief interruptions.**
*Medium · confirmed from source and Apple's docs · `winit/src/lib.rs:84-93, 252, 291`; `winit/src/conversion.rs:380`*

The hook passes winit's event through unchanged:

| Platform | What `Suspended` actually means |
|---|---|
| iOS | `willResignActive`. Fires for Control Center, Notification Center, Face ID sheets and calls. Real backgrounding only produces `WindowEvent::Occluded(true)`, which iced drops. |
| Android | Only the native window going away (`TerminateWindow`). Pause and Stop are not forwarded. |
| Desktop | Never fires. One `Resumed` arrives at startup. |

The doc's own example, "lock a wallet" (lib.rs:84-85), would lock every time the user pulls down Control Center. It could loop if unlocking triggers Face ID. The other example, "hide what is on screen", is well served on iOS.

**B2. The fork will be long-lived, and rebasing onto upstream master breaks the mobile builds.**
*Medium · confirmed with a trial rebase*

- Upstream will not merge mobile code, and the owner has opened no PRs there. Tawara's D32 plan to return the pin to crates.io will not happen through upstream.
- Master is 662 commits ahead, on wgpu 30, a git fork of winit (iced-rs/winit, objc2 0.6), and arboard.
- What a trial rebase showed:
  - 38237dd29 is already upstream and should be skipped.
  - 0b02176ee produces 2 conflict hunks and one type error: wrap a surface in `Some(..)` at master's lib.rs:1939.
  - 71f00e847 conflicts trivially.
- After the rebase, Android fails to compile in arboard 3.6.1, which has no Android module. iOS fails with the default `wayland` feature, through arboard → wl-clipboard-rs → wayland-backend. `scene.rs` still compiles, but the objc2 stack is duplicated.

**B3. Scene disconnect and reconnect can orphan the window.**
*Low (verifiers split low/medium) · reproduced only with a multi-scene probe; the single-scene trigger was not reproduced · `winit/src/scene.rs:58-61, 80-85, 115-155`*

`scene.rs` observes only `WillConnect` and `DidBecomeVisible`. If UIKit disconnects the scene to reclaim memory and later connects a new one in the same process, the existing window is never moved into it. The probe showed the new scene completely black. `SCENE` also keeps holding the disconnected scene. winit PR #4723 does not handle this case either.

**B4. `scene.rs` adopts windows and scenes that are not iced's.**
*Low · key-stealing reproduced in a probe · `winit/src/scene.rs:123, 138-162`*

There is no class filter: any UIWindow with no scene gets `makeKeyAndVisible`, which takes keyboard focus from iced. Any `UIWindowScene` role is accepted. The fix is to accept only `WinitUIWindow` windows and the application role. Keep replacing `SCENE` with newer application-role scenes rather than never overwriting it.

**B5. A UIScene symbol is hard-linked while Rust's default iOS deployment target is 10.0.**
*Low · confirmed with `otool` and `dyld_info` · `winit/src/scene.rs:53-56`*

`_UISceneWillConnectNotification` exists only on iOS 13 and later, and it is the only binding in the binary that needs more than iOS 10. On iOS 12 and older, dyld aborts at launch. Xcode 27's SDK minimum is 15.0, so in practice this is a metadata and template problem. Fix: set `IPHONEOS_DEPLOYMENT_TARGET=16.0` and a matching `MinimumOSVersion`.

**B6. On iOS, background rendering stops only by accident.**
*Low · confirmed · `winit/src/lib.rs:293-297, 891-896`*

`is_suspended` is never set on iOS. Rendering stops in the background only because winit always redraws through `setNeedsDisplay`/`drawRect`, and UIKit does not call `drawRect` for background apps. (winit's Metal detection at `winit ios/window.rs:525-526` compares a UIView to `CAMetalLayer`, so it is always false.) iced also ignores `Occluded` and `MemoryWarning`.

A separate claim that iced keeps presenting Metal frames in the background was refuted: a simulator run showed zero redraws over 19 s while backgrounded with a background task held.

**B7. On native targets the wgpu device request has no GLES 3.0 fallback, and its fallback caps textures at 2048.**
*Low · upstream code, confirmed from source · `wgpu/src/window/compositor.rs:147-158, 275-277`*

- The fallback `downlevel_defaults()` limits need compute and storage buffers, so GLES-3.0-only GPUs fail both requests.
- That fallback is also not passed through `using_resolution`, so its device caps textures at 2048. Surface setup then fails with `TooLarge` on phones larger than 2048 px.
- The backend can only be chosen through environment variables.

**B8. Mobile iced work is split across several efforts.**
*Low*

- Leinnan/iced_mobile has the same repo name, uses `.mobile_run()` on 0.14.0, and has no UIScene support.
- The iced-mobile org's fork uses `run_android(app)` on 0.15-dev, is Android-only, and loads `/system/fonts`.
- ibaryshnikov/android-iced-example is an integration example.

GitHub repo search for "iced_mobile" hides forks by default, so this repo does not appear and Leinnan's is listed first. This fork is the only one that adopts UIScene.

### C. Missing pieces for a real app

**C1. No safe-area insets.**
*High · confirmed on iOS (the first button sits under the Dynamic Island); Android from source · `winit/src/window/state.rs:64, 145-153`*

- On iOS, `inner_size()` is the safe area (`winit ios/window.rs:186-194`), but `layoutSubviews` sends `Resized` with the full bounds (`ios/view.rs:65-96`), and iced uses that. iced exposes no insets.
- On Android, winit drops `ContentRectChanged` and `InsetsChanged` (`android/mod.rs:222-224, 294-297`). With targetSdk 35 or higher, edge-to-edge is enforced, and `content_rect` then reports roughly zero for the system bars. Real insets need `WindowInsets` through JNI.

Today the only option is hard-coded padding.

**C2. Text input is limited on both platforms.**
*Medium · confirmed from source; on the iOS simulator the keyboard appears and ASCII typing works · `winit/src/window.rs:278-303`*

- **(a) Composition.** Android NativeActivity sends key events only: no composition, autocorrect or swipe typing, and characters outside the key map are dropped. GameActivity does send `TextEvent`, but winit 0.30 and winit master throw it away (`android/mod.rs:476-478`). On iOS, winit's view implements only `UIKeyInput`, so there is no marked text either.
- **(b) Re-showing the keyboard.** If the user dismisses the keyboard while the field stays focused, tapping the field does not bring it back: `set_ime_allowed(true)` is only called on the None→Some transition.
- **(c) Keyboard height.** iced never learns it, so inputs near the bottom get covered.
- **(d) Secure entry.** `Purpose::Secure` is ignored on both platforms.

For a wallet, this means accented passphrases probably cannot be typed on Android.

**C3. The clipboard does nothing.**
*Medium · confirmed · `winit/src/clipboard.rs:57, 78`; `window_clipboard-0.5.x/src/platform/{ios,android}.rs:34-41`*

Both backends return `Unimplemented`. Reads fail silently and writes only log a warning. Paste and copy shortcuts in text widgets are unreachable anyway: they need Cmd/Ctrl modifiers, which mobile winit never reports, and there is no long-press edit menu. Tawara implements copy only, in its own code.

**C4. text_editor, rich-text links and pick_list menus mishandle touch.**
*Medium · confirmed from source; upstream behaviour · `widget/src/text_editor.rs:1287-1332`, `widget/src/text/rich.rs:414, 424`, `widget/src/overlay/menu.rs:452-474`*

- text_editor reacts only to mouse events, so a tap cannot focus it and the keyboard never appears. Focusing it from code does work.
- Links in rich_text and markdown cannot be tapped.
- The pick_list and combo_box menu selects on touch-down, so a long list cannot be scrolled.

**C5. Dark mode is never detected.**
*Medium · confirmed (simulator in dark mode rendered light) · `winit/src/lib.rs:254-261, 677-681`*

winit returns `None` for the system theme on both platforms and never sends `ThemeChanged`. The fork's oneshot from `resumed()` is read with `try_recv` before `resumed()` runs, so even a real value would be lost. Fix: read `UITraitCollection` on iOS and `AndroidApp::config().ui_mode_night()` on Android, then send the result through `NotifyTheme`.

**C6. Lifecycle events never reach the Elm loop.**
*Medium · confirmed · `winit/src/lib.rs:95-104`, `src/lib.rs:479`*

- `on_lifecycle(fn(Lifecycle))` stores a capture-less function pointer in a `OnceLock`. A second call is silently ignored.
- The hook cannot reach `update` or a subscription without a hand-built static-channel bridge, about 22 lines.
- `iced` does not re-export it.
- The enum is not `#[non_exhaustive]`, and `MemoryWarning` is not forwarded.

Upstream already has the pattern to copy: 0.14's `system::theme_changes()`, and master's `subscription::Event::PlatformSpecific` with `listen_url()`.

**C7. iOS window settings are missing or ignored.**
*Low · confirmed · `core/src/window/settings.rs:18-25`*

- `visible: false`, position, title, decorations, resizable, level and icon are all ignored on iOS.
- The window is shown as soon as it is created, so iced's hide-until-ready step is skipped.
- There is no iOS `PlatformSpecific` setting for orientations, status bar, home-indicator auto-hide, or screen-edge gesture deferral.

**C8. iOS hardware keyboards only deliver typed characters and Backspace.**
*Low · `winit ios/view.rs:337-353`*

Arrow keys, Escape and Cmd shortcuts never arrive.

**Refuted, so not listed above:** "surfaces rebuilt on Resume keep a stale size." AOSP always follows a new surface with `surfaceChanged`, and that produces a `Resized`, so at worst one frame is drawn at the old size.

## 3. How it could be improved: engineering roadmap

The steps are in order. Steps 1 and 2 are prerequisites for everything else.

1. **Version floors and guards (hours).**
   - Set `winit = "0.30.13"` and `softbuffer = "0.4.7"` in the workspace, then run `cargo update -p winit -p softbuffer`.
   - Add `not(target_os = "android"), not(target_os = "ios")` to the display-server check in `src/lib.rs:499-504`.
   - Make the mobile default font automatic. Change the cfg at `graphics/src/settings.rs:40` to `all(any(target_arch = "wasm32", target_os = "android", target_os = "ios"), feature = "fira-sans")`. Then enable `fira-sans` for those targets through a target-specific dependency in `renderer/Cargo.toml`, or call `db.set_sans_serif_family("Fira Sans")` in `font_system()`.
   - Change `.zip(statuses.into_iter())` to `.zip(statuses)` at `winit/src/lib.rs:1325`; upstream master already did.
2. **The example, CI and scripts from §4.** Without them, nothing below can be checked.
3. **Shell correctness, in `winit/src/lib.rs`.**
   - Add a `finished` flag to `Runner` so `process_event` returns early once the instance is done. This fixes the iOS abort. On mobile, log a warning and ignore `iced::exit()`.
   - Treat closing the last window as a logged no-op on mobile.
   - Replace `has_resumed` with a single `suspended` flag that starts out true on Android. Hold `Window::Open` back while suspended, and replay the held actions on every `Resumed`, not just the first.
   - Refuse a second window on Android, with a log message.
   - Make surface creation lazy, with `None` meaning suspended. Drop the old surface before creating a new one in the Lost path.
   - Add `log::error!` at the `Control::Crash` site, and panic on iOS, where `run` never returns.
   - Turn `RecreationAttempt` into a panic that names `configChanges` and `iced::exit`.
4. **Input.**
   - iOS: map `"\n"`/`"\r"` to Enter and `"\t"` to Tab (`conversion.rs`).
   - Call `set_ime_allowed(true)` again on a press inside an already-focused input.
   - Clear the touch cursor after the lift batch has been dispatched.
   - Scrollable: add touch slop that holds the press back from the content until tap-or-drag is decided, plus momentum. Have checkbox, toggler and radio commit on lift.
   - Add touch handling to text_editor and rich_text, and make the menu select on lift.
   - Present all of these as general touch fixes.
5. **Platform services in `iced_winit`.**
   - Safe area: add `window::Event::SafeAreaChanged(Padding)` and a `window::safe_area(id)` task. On iOS, compute it from `inner_position`/`inner_size` minus `outer_*` on every `Resized`. On Android, use `content_rect` now and JNI `WindowInsets` later.
   - Theme: read `UITraitCollection` (enable the objc2-ui-kit feature) and `ui_mode_night()`, again on `Resumed` and on Android `ScaleFactorChanged`.
   - Clipboard: `UIPasteboard` (objc2-ui-kit `UIPasteboard` feature) and `ClipboardManager` through `jni` plus `ndk-context`, porting Tawara's copy code and adding read.
   - An iOS `PlatformSpecific` mapped onto `WindowAttributesExtIOS`.
6. **Lifecycle API.**
   - Define `#[non_exhaustive] enum Lifecycle { Inactive, Active, Background, Foreground, MemoryWarning }`.
   - Add a `subscription::Event::Lifecycle` variant and `iced::system::lifecycle() -> Subscription<Lifecycle>`.
   - Map iOS `WillResignActive`/`DidBecomeActive` to Inactive/Active, iOS `Occluded` to Background/Foreground, and Android `TerminateWindow`/`InitWindow` to Background/Foreground (an approximation).
   - Keep the synchronous hook for must-run-now security actions, but make it `Box<dyn Fn + Send + Sync>`, allow several, and return a handle.
   - Set `is_suspended` on iOS from `Occluded`.
7. **Harden `scene.rs`.**
   - Filter on the window class and the application role; this needs the objc2-ui-kit `UISceneSession` feature.
   - Handle `UISceneDidDisconnectNotification` and keep a registry of winit windows, so they can be moved into a newly connected scene.
   - Check at startup that the manifest is present (see §4).
   - Evaluate winit PR #4723 as a replacement only once it handles reconnect.
8. **Decide whether to carry a winit fork.** iced-rs/winit is the precedent. Candidate patches:
   - Destroy → exit, plus allowing loop recreation (#4739)
   - GameActivity `TextEvent` → `Ime`
   - inset events
   - Return as Enter
   - `UITextInput`
9. **Testability.** Move the lifecycle bookkeeping into a small struct that compiles on every target and has unit tests. Extract the deadline-merge logic from 38237dd29 into `fn merge_flow(current, requested, now)` and test its case table.
10. **Prepare for 0.15.** Gate arboard off on android/ios (master already has a stub clipboard for wasm), port `scene.rs` to objc2 0.6, and drop 38237dd29.

### 4.3 API changes that turn silent failures into compile errors or clear panics

| Today | After |
|---|---|
| Separate `iced_winit` dependency needed for `set_android_app`/`on_lifecycle`; mismatched refs build two copies silently | `pub mod mobile` in `iced` re-exports `Lifecycle`, `on_lifecycle`, and, under `cfg(any(target_os = "android", docsrs))` with `doc(cfg)`, `AndroidApp`. Apps depend only on `iced`, so a duplicate copy cannot happen. |
| `set_android_app` must be called before `run()`; forgetting it panics at runtime | `Application::run_android(self, app: AndroidApp)`: the type system requires the handle. Keep `set_android_app` as deprecated. |
| `android_main` is hand-written; a wrong name or missing `#[unsafe(no_mangle)]` gives a missing-symbol error at startup | `iced::android_main!(path::to::run)` expands only on Android to the correct exported fn, installs `android_logger` (tag `iced`) and a logging panic hook, sets the app, and logs `run()`'s error. |
| Missing winit activity feature gives a confusing error deep in android-activity | `android-native-activity` is a default `iced` feature. Enabling both activity features gives android-activity's own clear "cannot be enabled at the same time" error. |
| Default font renders nothing | Fira Sans is the default on mobile automatically. |
| Missing Info.plist manifest: app killed silently | `scene::adopt()` reads `NSBundle.mainBundle.infoDictionary["UIApplicationSceneManifest"]`. If it is missing, it `eprintln!`s and `log::error!`s the exact plist snippet (stderr reaches `simctl launch --console-pty`), and panics in debug builds. |
| `RecreationAttempt` → `expect("Create event loop")` | Panic text: "android_main ran twice in one process: the iced loop exited or the Activity was recreated. Set android:configChanges (see examples/mobile/android/AndroidManifest.xml) and do not call iced::exit on Android." |
| `iced::exit()` aborts on iOS | `log::warn!("iced::exit is ignored on iOS")`, no abort |
| Compositor error dropped on iOS | `log::error!` on every platform; panic on iOS |
| Second Android window: wgpu-hal panic | `log::error!` and return the existing window id |
| Clipboard stub fails silently | `log::warn!` once: "clipboard is not implemented on iOS/Android" |
| `on_lifecycle` silently ignores a second call | Returns `Result<(), AlreadySet>` and is `#[must_use]`; `Lifecycle` becomes `#[non_exhaustive]` |

```rust
// src/lib.rs
use iced::widget::{button, column, text};
use iced::{Element, Font};

#[derive(Default)]
struct Counter { value: i64 }

#[derive(Debug, Clone)]
enum Message { Increment }

impl Counter {
    fn update(&mut self, message: Message) {
        match message { Message::Increment => self.value += 1 }
    }

    fn view(&self) -> Element<'_, Message> {
        column![text(self.value).size(50), button("+").on_press(Message::Increment)]
            .padding(48) // no safe-area API yet: keep clear of status bar and home indicator
            .into()
    }
}

pub fn run() -> iced::Result {
    iced::application(Counter::default, Counter::update, Counter::view)
        .default_font(Font::with_name("Fira Sans")) // without this, mobile text is invisible
        .run()
}

#[cfg(target_os = "android")]
#[unsafe(no_mangle)]
fn android_main(app: iced_winit::winit::platform::android::activity::AndroidApp) {
    android_logger::init_once(
        android_logger::Config::default().with_max_level(log::LevelFilter::Info).with_tag("iced"),
    );
    iced_winit::set_android_app(app);
    if let Err(error) = run() {
        log::error!("{error}");
    }
}
```

### 4.6 The one-command loop per platform

Every verb prints `CHECK PASS <name>` or `CHECK FAIL <name>: <reason>` and exits non-zero on failure. All output goes to `target/mobile/<platform>/` (`app.png`, `console.log`, `oslog.txt`/`logcat.txt`). `all` runs `doctor run shot logs`.

**iOS** (`scripts/mobile/ios.sh run && ios.sh shot`). This is the recipe verified on the iOS 27 simulator:

```sh
T=aarch64-apple-ios-sim; BIN=mobile; ID=rs.iced.mobile; OUT=target/mobile/ios; APP=$OUT/Mobile.app
IPHONEOS_DEPLOYMENT_TARGET=16.0 cargo build -p mobile --bin $BIN --target $T
rm -rf "$APP"; mkdir -p "$APP"; cp target/$T/debug/$BIN "$APP/"
sed -e "s/@BUNDLE_ID@/$ID/" -e "s/@EXECUTABLE@/$BIN/" -e "s/@MIN_OS@/16.0/" \
    examples/mobile/ios/Info.plist.in > "$APP/Info.plist"
plutil -lint "$APP/Info.plist"                                                      # CHECK plist
plutil -extract UIApplicationSceneManifest xml1 -o /dev/null "$APP/Info.plist"      # CHECK scene-manifest
codesign --force --sign - "$APP"
xcrun simctl install booted "$APP"
SIMCTL_CHILD_RUST_LOG=info xcrun simctl launch --console-pty --terminate-running-process booted $ID \
    > $OUT/console.log 2>&1 &
sleep 4
xcrun simctl spawn booted launchctl list | grep -q "UIKitApplication:$ID"          # CHECK alive (exit 0 from launch proves nothing)
xcrun simctl io booted screenshot $OUT/app.png                                      # shot
xcrun simctl spawn booted log show --last 2m --predicate "process == \"$BIN\"" > $OUT/oslog.txt
grep -q "failed to launch" $OUT/oslog.txt && echo "CHECK FAIL launch: see $OUT/oslog.txt"
```

`doctor` checks that the Rust targets are installed, runs `xcodebuild -version`, reads the SDK version with `xcrun --show-sdk-version`, and warns that the scene manifest is mandatory from SDK 27. It then boots or creates a simulator.

simctl cannot tap. For interaction, run `cargo test -p mobile` (iced_test) on the host, or use idb or another simulator input tool. To force the CPU renderer, set `SIMCTL_CHILD_ICED_BACKEND=tiny-skia`.

**Android** (`scripts/mobile/android.sh run && android.sh shot`). This is a portable version of Tawara-mobile's pipeline: no Gradle.

```sh
ID=rs.iced.mobile; OUT=target/mobile/android; BT=$ANDROID_HOME/build-tools/36.0.0
HOST=$(uname -s | tr A-Z a-z)-x86_64          # darwin-x86_64 or linux-x86_64; NDK must be >= r28 for 16 KB pages
TC=$ANDROID_NDK_HOME/toolchains/llvm/prebuilt/$HOST/bin
export CARGO_TARGET_AARCH64_LINUX_ANDROID_LINKER=$TC/aarch64-linux-android26-clang \
       CC_aarch64_linux_android=$TC/aarch64-linux-android26-clang AR_aarch64_linux_android=$TC/llvm-ar
cargo build -p mobile --lib --target aarch64-linux-android
grep -q 'uiMode' examples/mobile/android/AndroidManifest.xml                         # CHECK configChanges
$BT/aapt2 link -o $OUT/base.apk --manifest examples/mobile/android/AndroidManifest.xml \
    -I $ANDROID_HOME/platforms/android-36/android.jar
mkdir -p $OUT/lib/arm64-v8a && cp target/aarch64-linux-android/debug/libmobile.so $OUT/lib/arm64-v8a/
(cd $OUT && zip -0 -r base.apk lib)                    # stored, because extractNativeLibs=false
$BT/zipalign -f -P 16 4 $OUT/base.apk $OUT/aligned.apk
$BT/apksigner sign --ks $OUT/debug.keystore --ks-pass pass:android --out $OUT/mobile.apk $OUT/aligned.apk
adb install -r $OUT/mobile.apk && adb shell am start -n $ID/android.app.NativeActivity
sleep 4; adb shell pidof $ID                                                          # CHECK alive
adb exec-out screencap -p > $OUT/app.png                                              # shot
adb logcat -d -s RustStdoutStderr:V RustPanic:V iced:V > $OUT/logcat.txt             # logs
```

`android.sh check` runs `cargo check --target aarch64-linux-android -p mobile`, which needs no NDK. `android.sh lifecycle` runs `adb shell cmd uimode night yes`, waits, then fails if `adb logcat -d -b events` shows `(am|wm)_destroy_activity` for the package or `ANR in`. A hung app keeps its PID, so `pidof` alone is not a valid check here. Interaction uses `adb shell input tap X Y` and `adb shell input text …`.

```markdown
# AGENTS.md

iced 0.14.1 (Rust, Elm-style GUI) with Android and iOS support. Read this before writing or changing mobile code.

## 1. Where things are
- Mobile code: branch `mobile/0.14` (was `tawara/0.14-mobile`), tags `v0.14.1-mobile.N`.
  `master` is plain upstream iced with NO mobile code. Always pin a tag or rev.
- Upstream iced declined mobile support (iced-rs/iced#302, #3099). Don't send mobile PRs upstream.
- The whole mobile delta (~400 lines) is in:
  `winit/src/lib.rs` (Android app handle, suspend/resume, `on_lifecycle`),
  `winit/src/scene.rs` (iOS UIScene), `winit/src/conversion.rs` (mobile keys, iOS window size),
  `winit/src/window.rs` (optional surface).
- Working app: `examples/mobile/`. Templates: `examples/mobile/android/AndroidManifest.xml`,
  `examples/mobile/ios/Info.plist.in`.

## 2. Using it in an app
Copy `examples/mobile/Cargo.toml`, `src/lib.rs`, `src/main.rs`. Rules; each one fails silently
or with a misleading error if broken:
1. `iced` and `iced_winit` use the same git URL and the same tag/rev string. Mixing branch and rev
   builds two copies: Android panics "Call iced_winit::set_android_app ... first" although you did,
   and on iOS the `on_lifecycle` hook never fires. Check: `cargo tree -d | grep iced_` prints nothing.
2. Android: a direct `winit = { version = "0.30.13", default-features = false,
   features = ["android-native-activity"] }`; `crate-type` includes `cdylib`;
   `#[unsafe(no_mangle)] fn android_main(app)` calls `iced_winit::set_android_app(app)` before `run()`;
   manifest `android.app.lib_name` == `[lib]` name.
3. Android manifest keeps the full `android:configChanges` list from the template. Missing entries
   freeze the app (ANR) on rotation, dark-mode, locale or font-scale changes.
4. iOS: Info.plist has `UIApplicationSceneManifest` (template). Without it an iOS 27 SDK build is
   killed at launch and `simctl launch` still exits 0. Set IPHONEOS_DEPLOYMENT_TARGET=16.0.
   `run()` never returns on iOS.
5. Never call `iced::exit()` or close the last window on mobile. iOS aborts; Android cannot relaunch
   in the same process; a closed last window leaves a dead black screen.
6. Keep iced's default features (or at least `x11`). They are inert on mobile.
7. Pad the root view for status bar / notch / home indicator. There is no safe-area API yet.
8. Install a logger (the example does: android_logger, oslog). iced logs through `log`; without
   a logger you see nothing.

## 3. Build, run, verify
Every verb prints `CHECK PASS <name>` or `CHECK FAIL <name>: <reason>`; output in `target/mobile/<platform>/`.

    scripts/mobile/ios.sh doctor | check | run | shot | logs | all
    scripts/mobile/android.sh doctor | check | run | shot | logs | lifecycle | all

- After `run`, always `shot` and look at the PNG. Blank buttons = font problem. Home screen = app died
  (read `oslog.txt`). Frozen after `lifecycle` = configChanges problem.
- `cargo check --target aarch64-linux-android` needs no NDK. `cargo build` does (NDK >= r28).
- Interaction: Android `adb shell input tap X Y` / `input text`. iOS: simctl cannot tap; test view
  logic on the host with `cargo test -p mobile` (iced_test, 390x844).
- CPU renderer: iOS `SIMCTL_CHILD_ICED_BACKEND=tiny-skia`; Android: `adb shell setprop debug.iced.backend tiny-skia`
  (read by the example).

## 4. Known limitations (don't debug these by trial and error)
| Area | Status | Do this |
|---|---|---|
| Safe area | not exposed | pad the root |
| Clipboard | stub on both | platform glue (UIPasteboard / JNI ClipboardManager) |
| Android IME | key events only: no composition, accents/CJK unreliable | test on device; document |
| Scroll list of buttons | drag starting on a row doesn't scroll | leave gaps / non-interactive rows until fixed |
| text_editor / rich-text links | ignore touch | focus programmatically |
| Dark mode | never detected | read platform setting yourself |
| `Lifecycle::Suspended` | iOS: inactive (Control Center, Face ID); Android: window lost | don't lock on it alone |
| Multiple windows on Android | panics | one window |
| iOS Return key | doesn't submit (until fixed) | add a submit button |

## 5. Changing the fork
- Mobile code is cfg-gated, so a host build proves nothing. Run:
    cargo check -p iced_winit --target aarch64-apple-ios
    cargo check -p iced_winit --target aarch64-apple-ios-sim
    cargo check -p iced_winit --target aarch64-linux-android --features winit/android-native-activity

  The workspace `cargo lint` alias is red on current stable because of upstream code
  (first failure graphics/src/geometry/cache.rs:119). Don't fix upstream lints in mobile commits.
- Keep the diff small and inside `winit/`: this fork is rebased onto upstream releases.
- Commits: `winit: <imperative summary>`, with a body saying why and what was checked
```

1. **Who is this fork for?** If it is only Tawara's dependency, a minimal diff plus AGENTS.md is enough. If it is meant as a general mobile iced, the P1 API work (re-exports, `run_android`, the lifecycle subscription) is worth doing.
2. **Should the fork carry its own winit patches?** The freeze on Activity recreation (A3), lost Android composition text (C2) and insets (C1) can only be fixed properly in winit, for example by adopting #4739.
3. **Stay on 0.14 or track 0.15?** The 0.15 rebase means gating arboard off mobile, porting `scene.rs` to objc2 0.6, and moving to wgpu 30. An alternative is an app-owned shell on the crates.io `iced_*` crates.
4. **Merge efforts with the iced-mobile org?** It has `run_android(app)` and Android font loading; this fork has the iOS UIScene work. Aligning names now avoids two incompatible APIs.
5. **NativeActivity or GameActivity, for a wallet?** NativeActivity cannot do IME composition, so accented passphrases are at risk. GameActivity needs Gradle and a winit patch. Is Java/Gradle acceptable, or is a JNI `InputConnection` preferred?
6. **May Tawara's platform glue move into the fork?** That covers clipboard copy through JNI and UIPasteboard, Back through JNI, and the build scripts.
7. **Minimum OS versions?** Proposed: iOS 16 and Android minSdk 26 / targetSdk 36. Confirm before they go into the templates and CI.

I checked upstream #302, #2952, #3099, #3245 and #2004 with `gh`, and the quote is accurate. I put the §4.4 "Today" sample in a scratch crate with path deps instead of git and a fresh resolve. It passes `cargo check` on aarch64-linux-android, aarch64-apple-ios and aarch64-apple-ios-sim, and `cargo build --release` links on aarch64-apple-ios. With the repo's lockfile it fails on Android inside softbuffer 0.4.6. Scratch: `<scratch>`

1. **§1 claim is wrong: "no duplicate objc2 on iOS".** This is only true with the repo's stale lockfile. Under a fresh downstream resolve, or after the report's own P0 softbuffer floor, softbuffer 0.4.8 brings in objc2 0.6.5 and objc2-foundation 0.3.2 next to winit's and `scene.rs`'s 0.5.x. Evidence: `cargo tree -d --target aarch64-apple-ios` in the scratch app, and `cargo tree -i objc2@0.6.5`, which leads to softbuffer 0.4.8. Reword it as: `scene.rs` adds no extra copy, but the objc2 stack is already duplicated.

2. **A1, §3 step 1 and P0 font fix: Fira Sans only fixes Latin, Greek and Cyrillic.** I parsed the cmap of `graphics/fonts/FiraSans-Regular.ttf`. It has 1687 codepoints and none for CJK, kana, Hangul, Arabic, Hebrew, Devanagari, Thai or emoji. After the fix, Japanese or Arabic input in a text_input is still invisible.
   - Add: load the platform font directory in `font_system()` (`graphics/src/text.rs:116-134`) with fontdb's `load_fonts_dir`. On Android that is `/system/fonts`; the iced-mobile org fork already does this (report B8). On iOS it is the system fonts directory, but read access from the sandbox must be checked on a device. Keep Fira Sans as the Latin default.
   - Workaround available to apps today: `iced::advanced::graphics::text::font_system()` → `raw()` → `db_mut().load_fonts_dir(..)` (`graphics/src/text.rs:145`, `src/advanced.rs:25`).
   - Add this to the AGENTS.md known-limitations table.

3. **Licensing and fork hygiene are not covered.**
   - Fira Sans is under OFL 1.1 (font name table entries 13 and 14). The repo ships no OFL text: `git ls-files` shows only `LICENSE` and `core/src/layout/DRUID_LICENSE`. If Fira Sans becomes the mobile default, every app embeds it, so add `graphics/fonts/OFL.txt` and tell apps in MOBILE.md to ship the notice.
   - Several things still point at upstream: `Cargo.toml:162` (`repository = "https://github.com/iced-rs/iced"`), the README badges and the issues link (`README.md:9,11,58`).
   - Issues are turned off on the fork (`gh api` reports `has_issues=false`), so bug reports can only go upstream, which closes mobile issues.
   - The GitHub description already says "with mobile support", but the default branch `master` has none. That makes trap #1 worse.
   - crates.io does not accept a library whose dependencies come from git. So nobody can publish a library built on this fork, which works against Tawara's stated goal (D32) of letting other apps build on it.

4. **The build and release path is not covered.** §4.6 stops at a simulator build and a debug APK.
   - iOS device builds need a real signing identity and a provisioning profile. The ad-hoc `codesign -` signature only works on the simulator.
   - App Store: `nm -u` on a release build of the §4.4 sample shows `_stat`, `_fstat`, `_fstatat` and `_mach_absolute_time`. These are on Apple's required-reason API list, so the app needs a `PrivacyInfo.xcprivacy` declaring the FileTimestamp and SystemBootTime categories. Without it, App Store Connect rejects the upload with ITMS-91053.
   - A store Info.plist also needs `CFBundleShortVersionString`, `UIDeviceFamily` and the supported orientations.
   - Google Play requires an AAB (built with bundletool) signed with a release keystore.
   - The proposed Ubuntu KVM emulator job runs on x86_64, so it needs an `x86_64-linux-android` build. Otherwise it depends on the system image having ARM translation.
   - Fix: add `release` verbs to the scripts, or state in AGENTS.md that release builds are out of scope.

5. **The §4.6 Android recipe fails on a clean checkout.**
   - `aapt2 link -o $OUT/base.apk` runs before anything creates `$OUT`; `mkdir -p $OUT` only appears later.
   - `apksigner --ks $OUT/debug.keystore` assumes a keystore that no step creates. Add a `keytool -genkeypair` step.

6. **The configChanges list is incomplete (§4.5 and AGENTS rule 3).** It is missing `fontWeightAdjustment` (API 31, the "Bold text" accessibility toggle), `grammaticalGender` (API 34), `colorMode`, `touchscreen` and `mcc|mnc`. Any of these recreates the Activity, which triggers the A3 freeze. Reference: https://developer.android.com/guide/topics/manifest/activity-element#config. `android.sh lifecycle` only toggles uiMode. Add rotation (`settings put system user_rotation`), `font_scale` and `font_weight_adjustment`.

7. **The draft AGENTS.md contradicts itself and the rest of the report.**
   - §5 says "Keep the diff small and inside `winit/`", but the report's own P0–P3 work touches `graphics/src/settings.rs`, `renderer/Cargo.toml`, `src/lib.rs`, `widget/` (scrollable, checkbox, toggler, radio) and core window events. Replace it with a list of allowed areas plus "cfg-gate it, or make it a general touch fix; one concern per commit".
   - §1's line that the whole delta is in `winit/` becomes false once P0 lands.
   - Rule 6 ("keep default features, or at least `x11`") is obsolete once the display-server exemption lands, and the draft says it assumes P0 has landed.
   - "`cargo check --target aarch64-linux-android` needs no NDK" is only true with native-activity. With game-activity, android-activity's `build.rs` compiles C++ through `cc` (`android-activity-0.6.1/build.rs:1-40`). This matters for open question 5.
   - **Host tests miss mobile bugs.** iced_test's `click()` sends mouse events only (`test/src/simulator.rs:361-367`), and `Simulator` runs the view without the winit shell. So the A2/A6/C4 regressions never show up in host tests. AGENTS.md should require touch events through `simulate([Event::Touch(FingerPressed{..}), FingerMoved{..}, FingerLifted{..}])`, and iOS-shaped key events such as `Key::Character("\n")`.
   - `SIMCTL_CHILD_RUST_LOG=info` does nothing with the §4.4 oslog logger, whose level is fixed in code. `log` output goes to os_log, so `--console-pty` only shows `eprintln!` and panics.

8. **Some recommendations don't fit iced's architecture.**
   - **Breaking enum changes (§3 steps 5–6).** `core::window::Event` (`core/src/window/event.rs:8`) and `subscription::Event` (`futures/src/subscription.rs:17`) are not `#[non_exhaustive]`. Adding `SafeAreaChanged` or `Lifecycle` variants therefore breaks downstream exhaustive matches, while the crate versions stay 0.14.1 to keep `[patch.crates-io]` working. Either document it as a breaking tag, or put these signals behind new types in `iced::mobile`.
   - **Theme refresh depends on a winit bug.** The Android theme refresh "on ScaleFactorChanged" only works because winit reads the old and new scale from the same call. As a result, every ConfigChanged emits ScaleFactorChanged (`winit-0.30.13/src/platform_impl/android/mod.rs:245-263`). Note this in the code.
   - **Default activity feature can lock out GameActivity (P1).** Cargo merges features across the whole dependency graph. If any crate in the graph uses `iced` with default features, which third-party widget crates usually do, native-activity is forced on. GameActivity then becomes impossible ("cannot be enabled at the same time", `android-activity-0.6.1/src/lib.rs:344-347`), even if the app itself sets `default-features = false`.

9. **CI prerequisites are missing.**
   - Enabling Actions on the fork also runs the 7 inherited upstream workflows. `lint.yml` (`cargo lint`) is red. `document.yml` deploys to iced-rs/docs on master pushes using `secrets.DOCS_DEPLOY_KEY`, which the fork doesn't have, so it fails. `build.yml` would run too. Disable or prune them on the mobile branch.
   - The proposed `cargo clippy -p iced_winit --no-deps -- -D warnings` step currently fails only at `winit/src/lib.rs:1325`. With that lint allowed, both the iOS-sim and Android (native-activity) runs pass. So the P0 zip fix must land before this CI, and the report should say so.

10. **Upstream sync is only covered for the 0.15 rebase.**
    - The local clone has only `origin`, no upstream remote.
    - Document the 0.14.x patch flow: add `upstream`, rebase `mobile/0.14` onto `upstream/0.14` whenever upstream cuts a 0.14.x release, re-tag `-mobile.N`, and never move existing tags.
    - Supporting evidence: in #3245, hecrj answered "It depends, but probably not" to PRs that would only add hooks for an external mobile crate. That strengthens B2, and weakens open question 3's alternative of an app-owned shell built on the crates.io `iced_*` crates.

11. **Minor correction to C5.** The oneshot from `resumed()` and its `try_recv` are upstream code, not fork code (`winit/src/lib.rs:254-261` and `677-681`; they appear only as context lines in the diff). On Android the theme is sent before the deferred actions are replayed, so only iOS loses the value. This changes nothing in practice, because winit returns `None` for the theme on both platforms.
